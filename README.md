# duet2-alignment — юстировка оптики шаговыми двигателями (Duet 2 WiFi)

Веб-приложение для управления шаговыми двигателями платы **Duet 2 WiFi**
(прошивка RepRapFirmware) по HTTP — для юстировки оптических элементов.

> Статус поддержки: mock-режим протестирован полностью. Интеграция с реальной платой рассчитана на RepRapFirmware 2.x/3.x, но требует проверки на конкретной версии прошивки и конфигурации машины.

## Возможности
- Работа через IP платы (режим GET/POST по HTTP API RepRapFirmware).
- Движение подвижек вперёд/назад с заданным шагом (кнопки +/−).
- Задание шага (мм) и скорости (мм/мин).
- Отдельное окно с текущими координатами (`/static/position.html`).
- Настройка токов (M906) и скоростей (M203) в `config.json`.
- Макросы «название → позиция системы» в `macros.json`.
- Псевдонимы осей (например, X → «Зеркало внутри камеры»).
- Mock-режим для отладки без платы.
- Серверная валидация осей, шага, скорости и макросов.
- Подтверждение перед запуском абсолютных макросов.
- Хоуминг — возврат в сохранённую позицию хоум (`/api/home`).
- Режимы выключения: вернуть в хоум или запомнить текущую позицию как новый хоум (старый — в макрос «предыдущий хоум»).
- 5–6 настраиваемых шагов (±) на каждую ось, с флажком «применить симметрично».
- Raw `/api/gcode` по умолчанию отключён.

## Ограничения и безопасность
- По умолчанию сервер слушает только `127.0.0.1`, а `debug=false`.
- Перед движением приложение валидирует оси против `config.json` и ограничивает шаг/скорость сервером.
- Для осей с `require_homed=true` движение блокируется до проверки homing (если проверка недоступна и `allow_unverified_homing=false`).
- Макросы — это **абсолютные координаты** (`G90` + `G1 ...`), поэтому они опаснее одиночных относительных шагов.
- Перед использованием на реальной механике обязательно проверь `min/max` пределы, корректность нуля и поведение после homing.

## Хоуминг и выключение
- `home_position` в `config.json` задаёт «хоум» — сохранённую опорную позицию (по умолчанию нули).
- Каждая ось имеет флаг `has_endstop`:
  - `true` — у оси есть концевик, хоуминг идёт физически через `G28`;
  - `false` — концевика нет, хоуминг идёт «мягко» — перемещение в `home_position`.
- `/api/home` (кнопка «Вернуть в хоум») — хоуминг: `G28` для осей с концевиками и soft-перемещение для остальных.
- `/api/shutdown` — подготовка к выключению платы:
  - `mode=go_home` — вернуть двигатели в хоум (как `/api/home`) и отключить их (`M18`);
  - `mode=keep_position` — оставить двигатели на месте, сделать текущую позицию новым хоумом, а старый хоум сохранить в макрос «предыдущий хоум».
- Для физического `G28` на плате должны быть настроены endstop'ы (M574) и, при необходимости, `home*.g` в `config.g`.

## Запуск
```bash
pip install -r requirements.txt
python app.py
```
Открыть в браузере: http://127.0.0.1:5000

## Структура
- `app.py` — Flask-сервер (маршруты API + отдача интерфейса).
- `duet_client.py` — обёртка HTTP API платы (RRF 2.x/3.x) + mock.
- `config.json` — IP, пароль, имена осей, токи, скорости.
- `config.json` также задаёт `max_step_mm`, политику homing, bind-host и флаг raw G-code.
- `macros.json` — макросы.
- `static/` — веб-интерфейс (index.html, app.js, style.css, position.html).
- `docs/` — скачанная документация Duet.

## HTTP API платы (кратко)
- RRF 3.x (основная целевая схема): `POST /machine/code` `{"code":"G1 X10 F600"}`; `GET /machine/axes`; `GET /machine/connect`.
- RRF 2.x (ограниченная совместимость): `GET /rr_gcode?gcode=...`; `GET /rr_status`; `GET /rr_reply`; `GET /rr_connect`.

## Полезные G-коды
- `G1 X10 F600` — сдвинуть X на 10 мм со скоростью 600 мм/мин.
- `G90` / `G91` — абсолютные / относительные координаты.
- `M114` — текущие координаты.
- `M906 X1000` — ток двигателя X, мА.
- `M203 X600` — максимальная скорость X, мм/мин.
- `M17` / `M18` — включить / выключить двигатели.

## Как добавить двигатель (ось)

Двигатели **не определяются автоматически** — их нужно описать в двух местах:
сначала в прошивке платы (`config.g`), затем в `config.json` приложения.

### Шаг 1. Прошивка платы (`config.g` на SD-карте, папка `/sys`)

На плате Duet 2 WiFi пять гнёзд драйверов: `X`, `Y`, `Z`, `E0`, `E1` (номера 0–4).
Ось привязывается к драйверу и настраивается G-кодами:

| Команда | Назначение | Пример |
|---------|-----------|--------|
| `M584` | привязка оси к драйверу | `M584 X0 Y1 Z2` |
| `M569` | направление вращения (полярность) | `M569 P0 S1` |
| `M350` | микрошаг | `M350 X16 Y16 Z16 I1` |
| `M92` | шагов на мм (геометрия механики!) | `M92 X80 Y80 Z400` |
| `M906` | ток двигателя, мА | `M906 X1000 Y1000 Z1000` |
| `M203` | макс. скорость, мм/мин | `M203 X600 Y600 Z600` |
| `M201` / `M566` | ускорение / jerk | `M201 X1000 Y1000 Z200` |
| `M208` | пределы хода (min:max) | `M208 X0:50 Y0:50 Z0:20` |
| `M574` | концевики (endstop) | `M574 X1 S1 P"xstop"` |

Минимальный пример `config.g` для трёх подвижек:

```
M584 X0 Y1 Z2          ; X -> драйвер 0, Y -> 1, Z -> 2
M569 P0 S1
M569 P1 S1
M569 P2 S1
M350 X16 Y16 Z16 I1    ; микрошаг 16x
M92 X80 Y80 Z400       ; шагов/мм — считается под конкретную механику!
M906 X1000 Y1000 Z1000 ; токи, мА
M203 X600 Y600 Z600    ; скорости
M201 X1000 Y1000 Z200  ; ускорения
M566 X600 Y600 Z60     ; jerk
M208 X0:50 Y0:50 Z0:20 ; пределы
```

> `M92` (шагов/мм) зависит от двигателя, микрошага и механики (шаг винта/редукция).
> Неверное значение — ось едет не туда или не на ту величину.

### Шаг 2. Приложение (`config.json`)

Добавь ось в массив `axes` с теми же буквами, что и в `config.g`:

```json
{
  "letter": "X",
  "name": "Зеркало внутри камеры",
  "current_mA": 1000,
  "speed_mm_min": 600,
  "max_step_mm": 1.0,
  "allow_absolute": true,
  "require_homed": true,
  "has_endstop": false,
  "steps": [
    { "plus": 0.01, "minus": 0.01 },
    { "plus": 0.05, "minus": 0.05 },
    { "plus": 0.1, "minus": 0.1 },
    { "plus": 0.25, "minus": 0.25 },
    { "plus": 0.5, "minus": 0.5 },
    { "plus": 1.0, "minus": 1.0 }
  ]
}
```

Поля оси:
- `letter` — буква оси (одна заглавная), должна совпадать с `config.g`;
- `name` — отображаемое имя в интерфейсе;
- `current_mA` — ток (`M906`), мА;
- `speed_mm_min` — разрешённая скорость (`M203`/`F`), мм/мин;
- `max_step_mm` — максимальный одиночный шаг, мм;
- `allow_absolute` — разрешены ли абсолютные перемещения (макросы/хоум);
- `require_homed` — требовать homing перед движением;
- `has_endstop` — есть ли концевик (влияет на хоуминг: `G28` или soft home);
- `steps` — список предустановленных шагов (1–6), каждый с `plus` и `minus` (мм).

После правки `config.g` перезагрузи прошивку (или отправь `M98 P"config.g"`),
а изменения `config.json` сохраняются из интерфейса или вручную.

## Runtime-команды, которые использует приложение
- Для относительных подвижек: `G91`, `G1`, `G90`.
- Для абсолютных макросов: `G90`, `G1`.
- Для чтения координат: `GET /machine/axes` (RRF 3.x) или `M114` через `/rr_gcode` (RRF 2.x).
- Для настройки токов и скоростей: `M906`, `M203`.
- Для ручного управления питанием моторов (если включить raw endpoint и allowlist): `M17`, `M18`.

## Версии и совместимость
- **RRF 3.x — основная целевая схема**, наиболее проверенная по документации.
- **RRF 2.x — ограниченная совместимость**: координаты читаются через `M114` + `GET /rr_reply`, требуется отдельная проверка на конкретной прошивке.
- Mock-режим не гарантирует полное совпадение поведения с реальной Duet 2 WiFi/Ethernet.
- Реальную плату нужно отдельно проверить на: ответы `M114`, структуру `/machine/status`, политику пароля и сессии, восстановление после HTTP 401/503.
